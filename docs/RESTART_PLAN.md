# 重启计划

配套评审：[CODE_REVIEW.md](./CODE_REVIEW.md)。评审结论不变：`main`（`6269236`）不能直接给真实用户用。本文把“可以开始给公网用户用”定义成一个小得多的
MVP，并给出可以开成 GitHub issue 的拆分。

所有者已锁定的决定：**第一批用户公开注册，不做邀请制。** 这比邀请制多出一整层门槛：邮箱验证、跨 isolate
限流、生卡配额、生产 Cookie，以及错误响应里不能出现密钥或上游原文。这些都在 P0，不在“有用户之后再补”。

## 公开注册下的 MVP

MVP 的定义：一个没用过这个仓库的人，在手机浏览器打开公网
URL，用自己的邮箱注册并完成验证，生成一张日语卡片（句子、注音、图、音频），刷新后只在自己的历史里看到它，并且不能通过多注册或狂点把三家
API 打爆。

### 第一批用户会得到

- 公开注册、邮箱验证、用户名密码登录、退出。
- 验证通过后，每天最多生成 N 张卡片。建议 N = 10，与旧 PRD 已锁定的“每日 10 张新卡”相同。超额得到明确的中文提示，而不是
  500。
- 一张卡片：一句 N5 日语、汉字注音、一张图、一段音频。历史按时间倒序只显示成功的卡。
- 失败可重试。重试不重复扣费、不把失败句子算成已学过。

### 第一批用户明确没有

- 邀请码、好友、社交。
- 设置页里的个性化（退出登录可以留在现有设置页）。
- 聊天、AI 讲解、客户端自备 API key。
- 词卡、中文释义、回忆评分、间隔重复、按天学习统计。
- 付费墙。公开注册阶段用配额控制成本，不接支付。
- JLPT 等级选择。内部固定 N5。

好友入口建议先从底部导航拿掉，避免用户点进去看到“即将上线”。这是范围控制，不是新功能。

### 上线前必须同时为真的防护

对应评审 P0-3、P0-4、P0-5。少一条都不对公网打开注册。

1. **邮箱未验证不能生卡。** `requireEmailVerification`，并且 `POST /api/card` 自己再查一次
   `emailVerified`。发信失败时，生卡功能开关保持关闭。
2. **限流存在于 D1 或 KV，不在内存里。** 至少限制：同一 IP 的注册次数、同一 IP
   和账号的登录次数、验证信重发次数、同一用户同时只有一个进行中的生卡。
3. **配额在调用 DeepSeek / 火山 / MiniMax 之前占坑。** 用户日配额默认 10。另外要有一个与用户无关的全局日上限和
   `CARD_GEN_ENABLED` 开关，账单异常时可以立刻关掉生成而不关登录。
4. **生产会话。** `BETTER_AUTH_SECRET`、`baseURL`、`trustedOrigins` 来自 Worker 环境。Cookie 为
   `Secure`、`HttpOnly`、`SameSite=Lax`。源码里不再写死 `http://localhost:5173`。
5. **生卡是 POST，带幂等键。** 跨站顶层 GET 不能再触发生成。重复的 `Idempotency-Key` 返回同一张卡。
6. **响应里没有秘密。** 客户端只看到稳定错误码和中文文案。上游
   body、SQL、栈和密钥只进服务端日志。登录失败用统一文案，避免用原始错误枚举用户名。

建议的第一版配额（可以改数字，不要改顺序）：

| 动作     | 建议上限                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 注册     | 每 IP 每小时 5 次                                                        |
| 登录失败 | 每 IP 每 15 分钟 10 次                                                   |
| 验证信   | 每账号每小时 3 封                                                        |
| 生卡     | 每用户每天 10 张，且同时只允许 1 个 in-flight                            |
| 全局生卡 | 每天一个硬顶，默认先按内部试用预算手填，超了返回 503 `CARD_GEN_DISABLED` |

## 分阶段 backlog

### P0：没有这些就不要公开注册

目标是“陌生用户能完成一次安全的生卡闭环”，不是把旧 PRD 做完。

- 可部署的 Worker：`wrangler.jsonc`、D1 绑定、R2 绑定、ASSETS + SPA 回退、`pnpm dev` = `wrangler dev`。
- 请求路径只读 `c.env`。句子记忆和卡片历史改用 `env.DB`。删除运行时 D1 REST 客户端。`CLOUDFLARE_API_TOKEN` 只留给本机
  drizzle-kit。
- 认证生产配置、邮箱验证、持久化限流、生卡开关。
- `POST /api/card`：配额占坑、幂等、状态 `pending | ready | failed`、错误体不含上游原文。
- 探索页和历史页走这个契约。历史不展示 `failed` 和没有媒体的行。
- 一条手机宽度的冒烟路径写成 README 里的检查表，并至少有 hermetic 测试锁住 401 / 403 / 429 / 错误体。

### P1：第一批用户留下来之后马上要补

这些不挡住第一次公开，但会在几天内变成投诉或账单问题。

- 模型输出长度和“像一句日语”的校验，放在付费调用之前。
- 注音词典随构建发布；初始化失败不写入永久 `null`。探索页改渲染结构化注音，停止把 HTML 存进数据库。
- `packages/shared` 成为卡片、历史和错误码的唯一类型来源。删掉 `/api/chat/stream` 客户端。
- 生图改为异步：请求提交后返回卡片 id，前端轮询 `GET /api/card/:id`（这个 GET 只读状态，没有副作用）。避免在 Worker 里
  `sleep` 轮询火山。
- 自托管日文字体，页面标题和文案改为中文。不要依赖 Google Fonts。
- CI：`dprint check`、后端和前端 `tsc`、hermetic vitest。厂商真实调用挪到手动或每晚任务。
- 火山签名的固定矢量测试。MiniMax 若返回音频 URL，只允许指定主机。

### 以后再做

来自旧 PRD，现在没有数据模型，也没有第一批用户的证据。不要和 P0 并行开工。

- 词卡、中文释义、句中词汇/语法高亮。
- 回忆评分和间隔重复（`user_memory_state` 那套）。
- 按天的学习历史、连续天数、正确率。
- AI 讲解。若做，优先评估“用户自备 OpenAI 兼容密钥”，避免再把讲解费用加到服务端密钥上。
- 好友。底部导航在做出来之前不要承诺。
- 一次性付费。配额先承担成本控制。
- 等级选择和从 N5 往上解锁。

### Epic A — 公开注册的认证（P0，`area:auth`）

结果：陌生邮箱可以注册、验证、登录、退出；未验证账号不能生卡；正式域名的 Cookie 可用。

验收：

- 生产环境缺少自有 `BETTER_AUTH_SECRET` 时 Worker 拒绝就绪。不能停在 better-auth 1.3.25 的行为上：它会退回公开常量
  `better-auth-secret-123456789`，并且只打日志。验收时要断言实际使用的 secret 不是这个常量。
- `trustedOrigins` 和 `baseURL` 等于该环境的公网 origin。本地 origin 只出现在 dev 配置。
- 未点击验证信时，`POST /api/card` 返回 403 `EMAIL_UNVERIFIED`，日志里没有厂商请求。
- 同一 IP 连续注册超过上限得到 429，计数在两次冷启动之后仍然有效。
- 登录失败的 HTTP 正文和 toast 不区分“用户不存在”和“密码错误”。

### Epic B — 生卡配额、幂等和错误体（P0，`area:cards`）

结果：验证用户每天最多 10 张成功卡；重复提交和失败重试不会线性烧钱；浏览器看不到上游错误。

验收：

- 方法是 POST。`GET /api/card` 不再有副作用。
- 第 11 次成功请求返回 429 `QUOTA_EXCEEDED`，且该次没有火山/MiniMax/DeepSeek 调用（用假客户端测试）。
- 相同 `Idempotency-Key` 返回同一 `cardId`。
- 厂商失败后历史列表不出现这张卡，句子记忆里没有这句。响应 body 没有 `message` 字段。
- `CARD_GEN_ENABLED=false` 时返回 503，登录仍可用。

### Epic C — Cloudflare 运行时收口（P0，`area:deploy`）

结果：一个命令能在本地用绑定跑起来，部署配置在仓库里。

验收：

- 存在 `wrangler.jsonc`：D1、R2、ASSETS、SPA 回退。
- `cardHistory` 和 `sentenceMemory` 不再引用 `api.cloudflare.com`。
- Worker 的 secret 列表里没有 `CLOUDFLARE_API_TOKEN`。若曾经配过，轮换。
- `auth.ts` 使用相对路径 import。
- 手机直接打开 `/explore` 能拿到 SPA，而不是资产 404。
- README 写明本地 `wrangler dev` 和前端代理端口。

### Epic D — 前后端契约（P1，`area:contract`）

结果：卡片和历史的类型只有一份，聊天死代码离开主路径。

验收：

- `ExplorePage` 和 `HistoryPage` 从 `@jpcards/shared` 引入类型。
- shared 里不再保留 `difficulty: Easy|Normal|Hard` 那份未实现的 `Card`，除非单独标成未来模型并无人引用。
- 仓库里搜不到 `/api/chat/stream`。

### Epic E — CI（P1，`area:ci`）

结果：空仓库的 PR 能跑完检查，且不需要厂商密钥。

验收：

- GitHub Actions 跑 format、typecheck、test。
- `card.test.ts` 不再在 import 时构造真实 OpenAI 客户端。

### Epic F — 面向第一批用户的说明（P0 的收尾，可以和 A–C 并行写）

结果：使用者和下一任开发者知道这个网站现在只做什么。

验收：

## 第一轮工程任务

按依赖顺序做。前一项没有验收，就不要开始后面会返工的 UI 打磨。

### 第一周：运行时和公开注册防护

1. 加 `wrangler.jsonc` 和 `getConfig(env)`。把 `OpenAI`、火山、MiniMax 的构造从模块顶层挪到请求内。`auth.ts` 改为相对
   import。
2. 让 `insertCardHistory`、`getCardHistory`、`getRecentSentences`、`insertSentence` 接收 D1 drizzle。删掉 `d1Client.ts`
   的 REST 实现。本机 drizzle-kit 继续用 `.env` 里的 token。
3. 把 better-auth 接到绑定：`secret`、`baseURL`、`trustedOrigins`、Secure
   Cookie、`requireEmailVerification`。选一个发信渠道；渠道没落地时默认 `CARD_GEN_ENABLED=false`。
4. 用 D1 表做限流和配额（`rate_limit`、`card_quota`）。注册和登录走限流。这张表要能在测试里用内存或 Miniflare 断言。
5. 本地冒烟：Wrangler + Vite 代理，注册 → 收信验证 → 登录 → 确认生卡开关关闭时得到 503 而不是厂商调用。把步骤写进
   README。

### 第二周：生卡闭环和回归网

1. 卡片状态机和 `POST /api/card`。先占配额和幂等键，再调模型。失败回滚占坑。探索页改为 POST，历史只读 `ready`。
2. 错误码表放进 shared。后端响应删掉 `message`。前端对 403 / 429 / 503 显示固定中文。
3. hermetic 测试：未登录、未验证、超额、幂等重复、失败不写句子记忆、500 body 的键集合。
4. GitHub Actions 接上。根 `test` 脚本改为真正跑这些测试。
5. 处理导航和文案：标题、中文空状态、拿掉好友入口。关闭 issue #1。Epic F 的 README 替换空文件后，再决定草稿 PR #2、#3
   关闭。

第一轮结束时的演示应该是：公网 URL、两个不同邮箱、各自能看到自己的卡、第三个未验证邮箱不能生卡、把配额改成 1
之后第二次生成被拒绝。演示做不到，就还没有“真实用户可用”。
