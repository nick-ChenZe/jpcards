# API 文档索引与约定

本目录用于统一管理所有后端与前端调用的 API 文档。

## 目录目标

- 让接口定义可检索、可审查、可版本化。
- 让开发、测试、联调、验收使用同一份契约。
- 避免“代码先行但无契约”导致的接口歧义。

## 强制约定（必须遵循）

- 所有新接口在开发前必须先在 `docs/api/` 下补齐文档草案。
- 接口开发、联调与测试必须以文档中的字段、错误码、示例为准。
- 任何破坏性变更必须先更新文档并记录变更说明，再进入开发。
- 未记录在本目录中的接口，视为不受支持接口，不允许进入正式环境。

## 命名规范

- 使用有序前缀命名：`01-`、`02-`、`03-`。
- 文件名使用 kebab-case，表达“能力 + 结果”。
- 示例：`01-text-to-audio-hex.md`。

## 单接口文档模板

每个接口文档至少包含以下章节：

1. 接口目标与场景
2. 请求定义（Method、Path、Headers、Body）
3. 响应定义（成功/失败）
4. 字段约束与校验规则
5. 错误码与处理建议
6. 示例请求/响应
7. 安全与审计要求
8. 版本与变更记录

## 当前接口列表

- `01-text-to-audio-hex.md`：根据文本生成音频编码的十六进制字符串。
